# 解释权 · 定义权 · 话语权 · 展示页

单文件交互式电子书，用于介绍这套关于社会认知秩序的分析框架。**零外部依赖**，双击即可用浏览器打开。

## 理论一句话

三权理论是一套关于社会认知秩序如何被生产的分析框架：用「定义权 · 解释权 · 话语权」三个功能位置，
拆解同一件事为什么可以有不同名称、不同意义、不同抵达范围——并说明这三项能力如何分离、组合、转移与反噬。

## 科普向约定

- 每章开头先给具体案例（`.case-v`），**案例里不出现任何抽象术语**
- 术语首次出现先转译大白话，再给原文定义。如定义权 →「这到底是个什么东西」
- 交互提示写的是**动作句**（"点任一级，看那一级改变了什么"），不是描述句
- 每个交互结论标注书稿章节号，可回查原文
- 深度内容收进折叠区，不拆主线叙事

## 修复：概念地图展开后标签脱节 / 压住 / 挤出画布（本轮）

三个维度展开后，子节点标签脱离了各自的圆点、互相压住，底部还有两个被挤出画布。
根因四条，全部用数值仿真确认（不是目测）：

| 根因 | 实测 |
| --- | --- |
| 相邻子节点的**弦距小于标签宽** → 必然重叠 | 弦距 66.8–70.7px，标签宽 74–87px，最大重叠 20.2px |
| 用 `idx % 2` 把标签**垂直错开 28/60px** | 一半标签离自己的点 60px，视觉脱节 |
| `plate()` 的**垂直回退** `ly ± 20`（最多 5 次） | 会**翻转标签相对圆点的方位**：exp「第一解释」跑到圆点**下方** 12px、dis「抵达频次」跑到**上方** 32px；并打乱上下次序 |
| 接力标注固定画在中点 −11px，**无任何避让** | 9 个里 6 个压住标签 |
| exp 现状参数下底部两个标签越界 | 「责任分配」「证据资格」rect 是 y 679–707，画布高 700 → **超出 7px** |

改法三条：

1. **标签改为「沿自己的射线外移固定 26px」**，删掉垂直错开与 `above` 判断。
   用 `subPos()` 返回的 `a` 作方向（动画中 `p→0` 时圆点会收缩到节点中心，从坐标反推会得到零向量）。
   于是标签与圆点的距离**恒为 26px**、方位永远一致 —— 不再脱节、不再翻转。
2. **几何微调（节点坐标不动）**：`def` arc 2.0→2.1；`dis` base −0.35→−0.20、arc 2.0→1.9、dist 168→165；
   `exp` arc 2.2→**3.0**、dist 162→140。节点不动 ⇒ 三角结构与三条接力弧都不用改。
3. **`plate()` 的兜底改为「沿射线外推」**（18/36px 两档，只接受既不越界也不相撞的档位），
   方向沿射线所以永远不会翻转；几何已验证留有间隙，正常不触发，它是给真实字宽与估算有偏差时的保险。
4. **接力标注改两趟绘制**：先画连线，等子标签都进了 `placed` 之后再画标注，
   沿连线法线按 `[0, ±8 … ±56]` 试位取第一个不相撞的（实测 9 个全部放下，最大偏移 32px）。

**验收（断言直接读画布真实绘制的 `placed` 数组，不是重算）**：

- 三个维度：`dotCheck:[]`（每个标签距自己的圆点恒为 26px 且在外侧）、`overlaps:[]`、`outOfBounds:[]`
- **负对照**：把 `arc/dist` 改回旧值 → `outOfBounds:[2,3]`，精确重现「责任分配/证据资格」被挤出画布 ⇒ 判据不是空转
- 字宽核对：浏览器实测 4 字标签 `measureText` = 52px，与离线模型「每字 13px」逐字吻合
- 三档字号（sm / md / lg）下都 `ok:true`
- 折叠态**逐字节未变**：新旧页面 `atlas.toDataURL()` 长度与哈希完全相同（`86786 / 975496809`）
- 点击子节点仍弹出说明卡（`popup` = 「责任分配」）；回归 34 交互 / 0 空 / 0 失败 / 13 章 / 70 条目录；375px 无横向溢出

> **一个必须说明的造型取舍**：「解释权」在最下方，展开后只有 190px 竖向空间。
> 实测**任何朝向**都做不到半径 ≥155px，所以它的扇面只能「半径小 + 弧宽大」（172°，半径 140）。
> 相邻标签间距因此比另两个维度小。若想要与 `定义权` 一样舒展的深扇面，需要把该节点上移约 40px
> （y 510→470 时可用半径升到 185），但那会同时改动两条接力弧的控制点与标注位置。

## 修复：窄屏矩阵被挤成竖排单字（既有问题，非本轮引入）

改动前的备份同样在 `@media (max-width:760px)` 里没有矩阵规则，所以
`.mx-grid` 的多列网格在 375px 会被压成每个字一行。
现给网格套一层 `.mx-scroll`（在 `renderMatrix` 里包裹），窄屏改为横向滚动：
桌面端实测网格宽 = 容器宽 = 778px（不产生滚动条），375px 下网格 620px、容器 282px，可横向拖动。

## 修复：顶栏放大镜「点不开」（本轮）

根因是**状态类只在部分断点下有样式**：放大镜绑定的 `openUI()` 只给 `<body>` 加一个 `srch-open` 类，
而 `srch-open` 的**全部**样式都写在 `@media (max-width:1280px)` 里。
于是 >1280px 时点击等于加了个空类 —— 唯一变化是把光标塞进侧栏那个**本来就常显**的搜索框，
顶栏按钮自身零反馈，用户判定「点不开」。

改法：新增居中搜索面板（`.pal`，`z-index:200`），放大镜 / `/` / `⌘K` 一律唤出它，
任何宽度都有肉眼可见的响应；`openUI` 与 `srch-open` 整块删除。
匹配与渲染抽成共享引擎（`searchHits` / `hilite` / `countByKind` / `renderRows` / `scrollRowIntoView` / `goTo`），
侧栏内联搜索与面板各自只维护「容器是谁、关闭动作是谁」。

## 修复：搜索面板的分类胶囊点了没反应（本轮）

那 6 个胶囊（章 / 小标题 / 交互 / 图版 / 案例 / 折叠区）原本是 **`<span>`——没绑任何事件，连 `cursor` 都没设**，
却带着圆角边框和数字角标，长得就是可点的筛选 chip。它和「五步战局进度轨」是同一类错误：
**做成控件的样子，却没有控件的行为**。词条那一排（`.pal-word`）本来就是 `<button>`，实测一直是好的。

现在胶囊是真 `<button>`：

- 点某一类 → 列出该类全部条目（`<button class="pal-cat" data-k="h" aria-pressed>`）
- 再点同一个 → 取消；结果列表右上角另有「× 返回」
- **筛选态下胶囊保留在顶部并高亮**（`aria-pressed="true"`）—— 否则重渲染后连"选中了哪个"都看不见
- 开始打字自动退出分类视图（避免分类 + 关键词两层过滤互相打架）
- 键盘：胶囊进 `Tab` 循环（焦点陷阱选择器已从 `.sr-row` 扩为 `.sr-row,.pal-cat,.pal-word,.pal-back`）；
  重渲染会换掉按钮，所以点击后**手动把焦点还回同一个胶囊**，否则键盘 Tab 链在这里断掉
- 顺手补了 `:focus-visible` 焦点环与 `:active` 按下位移 —— 这类元素本来就该有，缺了就没法分辨"没效果"还是"没点到"

`renderRows()` 加了可选的 `headHTML` 参数（分类视图要自定义表头 + 返回键）；不给时行为与原来完全一致。

## 新增：快速入口的两个分组名（本轮）

原来快速入口只有一行总说明 + 两排胶囊，两排胶囊没有各自的名字，
读者不知道上面那排是「类型」、下面那排是「关键词」。现在给两排各加一个分组名：
**按类型浏览** / **常用关键词**（`.pal-lab`，沿用页面已有的等宽小标签语言）。

- 标签是纯文本 `<div>`，**不可聚焦**（`tabIndex === -1`），焦点陷阱的 Tab 序列不受影响
- 两个胶囊容器补了 `role="group"` + `aria-label`，屏幕阅读器也知道每组是什么
- 颜色用 `--ink-3` 而不是 `--ink-4`：它们是**分组名**不是刻度。
  面板底色上实测 `--ink-4` 只有 3.78:1（浅色）/ 4.07:1（深色），`--ink-3` 是 5.99:1 / 5.08:1。
  于是面板里形成清晰的层次：提示行（`--ink-4`）< 分组名（`--ink-3`）< 胶囊（`--ink-2/3` 带边框）
- 因为 `quickHTML()` 是默认态与分类筛选态共用的，**筛选态下分组名也照样在**（改一处、两个状态都生效）

## 修复：窄屏抽屉里的目录点不动（既有问题，非本轮引入）

`.scrim` 的 `z-index:130` 高于 `.rail` 的 `120`，所以抽屉展开时蒙层盖在侧栏之上：
`document.elementFromPoint()` 打在章节点中心返回的是 `scrim`，点下去既不跳转、只把抽屉关掉。
两个 z-index 都是原始文件里就有的值，属既有问题。
修法一行：`.rail.open{ z-index:135; }`（只影响展开态，仍低于顶栏 140 与搜索面板 200）。
修后实测该点命中 `rail-link`，点第 10 章时 `scrollY` 0 → 32935。

## 新增：页脚授权链接的浮层说明（本轮）

`CC BY-NC-SA 4.0` 现在和正文术语共用同一套浮层（`.term-pop`）：悬停或键盘聚焦弹出卡片，
内容为「授权协议 / CC BY-NC-SA 4.0 ＝ 署名 · 非商业性使用 · 相同方式共享 / 三条义务分别是什么」。
链接加了虚线底边作为「可展开」的视觉暗示，但**仍是链接**（点击照样跳 CC 官网，触屏行为不变）。

实现要点：
- 新增 `TIPS` 表，**独立于 `TERMS`** —— `TERMS` 的键会被拼进正文术语正则
  （`Object.keys(TERMS).join('|')`），而 `CC BY-NC-SA 4.0` 里的 `.` 是正则元字符，混进去会误匹配。
- 委托选择器从 `.term` 扩为 `.term,[data-tip]`，`show()` 拆出 `resolve()` 按属性分辨数据源，
  返回统一的 `{k, pl, d}` —— 两处触发源共用一套渲染。

## 修复：浮层的纵向翻转（本轮，顺带修的既有缺陷）

原 `place()` **只会把卡片放在元素下方**，而页脚是文档最后一个元素：链接下面只剩约 116px，
卡片约 222px 高 → 卡片会渲染到文档之外**根本看不见**。
现改为：先量卡片真实尺寸 → 下方放得下就放下方（与原行为逐像素一致）→ 放不下且上方放得下就**翻到上方** →
两边都放不下时选空间更大的一侧兜底。这条同时修好了页脚里术语卡片贴底的问题。

实测：链接在视口 y=773、卡片落在 y=542–764（**在链接上方**）且完全在视口内；
而「若不翻转则必然溢出」的前置条件同时成立 —— 两个断言一起才排除伪成功。

## 修复：浮层宽度 330 → 159 的回归（本轮引入并当场修掉）

把 `place()` 的横向右界从硬编码常量 `350` 改成实测宽度后，暴露出一个**循环依赖**：
`position:absolute` 且只设 `left` 时，元素宽度由「可用宽度 = 容器宽 − left」决定，
而 `left` 又由量到的宽度决定。旧代码因为 `350 > 330` 恰好绕过了它；改完在 375px 下
卡片被压成 **159px 宽**（一条又窄又高的文字柱）。

修法：给 `.term-pop` 加 `width:max-content`，让宽度**只由内容决定、与 `left` 无关**，
循环随之消失；`max-width` 改为 `min(330px, calc(100vw - 24px))` 保证极窄屏也不溢出。
实测 1440 / 375 下宽度均为 330px，375px 下卡片 `left:18 right:348` 完全在视口内。
