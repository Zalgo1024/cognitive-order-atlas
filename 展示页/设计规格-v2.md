## 一、总体形态

| | v1（已交付） | v2（本规格） |
|---|---|---|
| 结构 | 3 个 page（什么是 / 怎么分析 / 能做什么） | **13 节章节制**（导论 + 12 章），单页长滚动 |
| 导航 | 顶部 3 个按钮 | 左侧固定章节导轨 + 顶栏进度条 + 移动端抽屉 |
| 章节类型 | 全部含交互 | **纯阅读节 / 含交互节 明确区分**，章头打类型徽标 |
| 主题 | 仅深色 | **浅色 ⇄ 深色自由切换**，可记忆、跟随系统 |
| 交互组件 | 5 个一次性组件 | **一套可复用「交互原语」**（10 个），章节只是组合它们 |

原则：**不做 30 个一次性组件**。先把交互原语做成声明式工厂（`data-` 属性即可初始化），再逐章填充内容。这样 13 节可以分工推进而不互相冲突。

## 二、双主题系统

### 2.1 语义 token 化

现有 CSS 变量已经是语义化的（`--bg / --surface / --line / --ink-N / --def / --exp / --dis / --danger`），
只需把值抽成两套：

| token | 深色（默认） | 浅色 |
|---|---|---|
| `--bg` | `#0a0d12` | `#f7f8fa` |
| `--bg-2` | `#0e1319` | `#eef1f5` |
| `--surface` | `#131a23` | `#ffffff` |
| `--surface-2` | `#19222e` | `#f2f4f8` |
| `--line` | `#222c3a` | `#dde3ec` |
| `--line-hi` | `#3b4c62` | `#b9c4d4` |
| `--ink` | `#e9eef7` | `#151a22` |
| `--ink-2` | `#a2b0c6` | `#4a5568` |
| `--ink-3` | `#6b7b93` | `#6e7a8d` |
| `--ink-4` | `#4a5769` | `#9aa5b4` |
| `--def` | `#6ea8fe` | `#2f6fd8` |
| `--exp` | `#e0a458` | `#a86a12` |
| `--dis` | `#45d9b0` | `#0d8f72` |
| `--danger` | `#ff5c6c` | `#cc3346` |
| `--glow` | 40% 透明光晕 | 无光晕，改发丝阴影 |

浅色版不走三元页的暖米色，走**冷白纸 + 石墨字**，与深色版共享「制图／图册」气质。

### 2.2 切换机制

- `<html data-theme="dark|light">`，所有变量挂在 `[data-theme="..."]` 下
- **防闪烁**：`<head>` 内联一段极短脚本，在首次绘制前读取 `localStorage.theme`，否则用 `prefers-color-scheme`
- 顶栏右侧切换按钮，图标 `☾ / ☀`；点击写 `localStorage`
- 若用户从未手动切换，则跟随系统变化（监听 `matchMedia` change）

### 2.3 canvas 必须跟着换

图 01 的配色目前是硬编码 JS 常量。改为：

```js
function palette(){
  const cs = getComputedStyle(document.documentElement);
  const v = n => cs.getPropertyValue(n).trim();
  return { bg:v('--bg-2'), line:v('--line'), ink:v('--ink'), def:v('--def'), ... };
}
```

主题切换后重读调色板并 `drawUniverse()` 重绘。所有 `hexA()` 需兼容浅色下的非 hex 值（改为解析 rgb）。

- 导轨：13 个编号圆点；当前节高亮并自动滚动到可见位置；悬停显示章名；点击平滑跳转
- 顶栏进度条：按滚动位置计算，`IntersectionObserver` 标记当前节
- 移动端：导轨收成抽屉，由「≡ 章节」按钮唤出
- 章头徽标区分 `纯阅读` / `含 N 个交互`——让读者知道何时该动手，何时只需读

## 四、交互原语库（10 个）

每个原语用 `data-` 属性声明式初始化，例如：

```html
<div class="ix ix-chain" data-chain="fact-def-exp-dis-cognition" data-gates="2"></div>
```

| # | 原语 | 做什么 | 出现在哪些节 |
|---|---|---|---|
| P1 | **传导链 chain** | 一串节点 + 箭头；节点可标记 通过/受阻/未及；点击切换阻断；悬停出释义 | 导论、3（传播链）、6（五步战局）、7（叙事五环节）、10（扩散三路径） |
| P2 | **状态机 stepper** | N 个开关 → 实时输出一张结论卡（能够做到／卡在哪里／所处状态／说明） | 4（三权组合 8 状态）、8（四加固机制）、9（授权保障切断）、11（场域切换） |
| P3 | **滑块推演 slider** | 一个连续变量 → 输出条 + 阶段文案切换 + 阈值触发 | 1（例外清单）、2（因果起点）、3（频次→疲劳）、8（硬约束累积）、10（债务时钟）、11（符号磨损） |
| P4 | **矩阵 matrix** | 二维网格 + 轴标签；点格子在侧栏出详情 | 4（组合×场景）、6（操弄技术棋盘）、9（权力手段×三权效果）、11（五场域×三权，表5）、12（八位理论家×继承分歧） |
| P5 | **推演播放器 sim** | 点「推演」逐步高亮链条并逐条弹出解说，可暂停/重置 | 4（闭环四阶段+反哺）、6（危机抢夺）、7（叙事闭环）、9（不进场时间轴）、10（临界点形成） |
| P6 | **对照 compare** | 2–4 栏并排对照 | 2（个案 vs 结构）、8（三种结果）、9（压制 vs 信服）、10（失效 vs 反噬）、12（逐位理论家） |
| P7 | **层级阶梯 levels** | 垂直阶梯，逐级展开 | 5（认知形成：依赖→框架→参照→信任→注意）、11（场域迁移三阶段） |
| P8 | **连续体 spectrum** | 一条刻度尺，拖动/点击定位到某个刻度状态 | 8（三种沉默）、9（形式服从→实质接受）、11（符号磨损→掏空→重置） |
| P9 | **案例实验室 caselab** | 左侧选案例 → 右侧按六个维度自动填出分析 | 独立成节（见第六节），并从 1/2/6/7/10 章交叉链接 |
| P10 | **诊断工作表 workbench** | 六步追问链做成勾选清单，实时汇总成一段判断 | 独立成节，第 12 章后 |

保留现有 v1 的 **canvas 概念地图**作为第 4 节的图版（升级为可按章节聚焦高亮）。

## 六、四个"重器"（最能体现可操作性）

### 6.1 案例实验室 `caselab`

用书中自带的真实案例，一键生成三权拆解。左侧选案例，右侧六维展开：

- 案例池（全部来自原书，不虚构）：
  1. 工厂设备事故 —— 因果起点与责任分配
  2. 平台接单者的身份命名（合作伙伴／员工／用户）
  3. "零添加"食品标签与标准争夺
  4. 柴油技术的"清洁"标签回流
  5. 消费电子起火与解释重建
  6. 驾驶辅助系统命名争议
  7. 数据隐私平台的信誉反噬
  8. 某制造企业用工荒（三元页案例，可作跨理论对照）

- 六维输出：**定义**（谁命名、命名成什么）→ **解释**（谁定因果、责任落在哪层）→ **话语**（哪些渠道给了可见性）→ **权力**（授权/保障/切断做了什么）→ **叙事**（角色、因果、结局）→ **反噬**（债务在哪、临界条件是否具备）

这是全站最能让人"学会用"的模块。

### 6.2 操弄棋盘 `matrix`

三行（定义战／解释战／话语战）× 若干技术列，每格标注**它介入的认知环节**与**可观察的痕迹**。点击格子，右侧给出该技术的识别要点与反制位置。

### 6.3 场域矩阵 `matrix`

五类场域（政府／公司／组织机构／团队社群／数字平台）× 权力来源／三权分配／时间尺度／反噬形态。点击切换场域，内容区整体换一套数据——直观测到"同一句话在不同场域效力完全不同"。

### 6.4 诊断工作表 `workbench`

六步追问链变成可勾选清单：

1. 最初是谁为对象命名？→
2. 什么事实被放进了主要因果？→
3. 责任在何处停止？→
4. 哪些渠道让这个版本获得可见性？→
5. 对手被迫证明了什么？→
6. 最终哪套说法进入了记录与记忆？

每步给 3–4 个候选项，勾选后底部实时汇总成一段"本次竞争的三权结构判断"。
