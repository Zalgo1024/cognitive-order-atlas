## 理论内核（必须准确，不能讲错）
三权 = **功能性能力**，不是法定权利。判断标准是「实际是否生效」，不是「是否被允许」。

| 权 | 回答 | 作用位置 | 核心机制 |
|---|---|---|---|
| 定义权 | 这是什么 | 认知起点 | 命名→分类→划界→标准；压缩复杂现实为可识别对象；决定举证责任分配 |
| 解释权 | 为什么这样、这意味着什么 | 意义与责任 | 选择→连接→归因→定型；决定因果链起点与停止追问的位置 |
| 话语权 | 谁能被听见 | 可见性 | 资格→渠道→抵达→频次/覆盖→信任链→跨圈层；能说话≠有话语权 |

### 关键判断（原文金句级）
- 认知秩序 ≠ 共识。秩序发生在结论形成**之前**（概念、标准、渠道）。
- 权力 ≠ 三权。权力只改**条件**（授权、保障、切断），承认不能被生产。
  - 四种错配：有定义权无承认 / 有解释资格无信任 / 有渠道无概念 / 有强制无解释
  - 结尾句：「权力可以决定谁先跑，不能决定谁被相信。」
- 压制 ≠ 信服。压制边际成本递增、不自我维持；信服边际成本递减、可外包给受众。
  三种状态：形式服从 / 实质接受 / **沉默的服从**（多数压制实际买到的就是第三种）。
- 失效 ≠ 反噬。失效是模式失效（中性，可修正）；反噬是账户透支（有方向，须偿债）。
  判别指标不是声量，而是**原文本是否被反过来引用**。
- 三权闭环四阶段：启动（定义）→ 铺开（话语）→ 落地（解释）→ 反哺（重新分配）。
- 反噬三条件：落差可核验 + 连接者出现 + 通道存在。反噬三路径回流：渠道 → 信任链 → 制度，严重度递增。
- 三权集中 = 最强也最脆弱（信用共享 + 单点失效）。
- 降低反噬四条件：可修正性、解释冗余、渠道分散、信用储备。共同点：**都降低短期效率**。

### 有限状态表（第4、12章，理论的骨架）
- 单权三态：定义权→卡在扩散与意义；解释权→卡在对象与抵达；话语权→卡在内容与定型
- 两权三组合：定义+话语=**议题占位**（强在启动扩张，弱在无解释收束）；
  定义+解释=**意义闭合**（强在法律行政，弱在无外部扩散）；
  话语+解释=**快速定性**（强在舆论危机，弱在被困对方概念）
- 三权齐备=闭环控制；**三权尽失=认知消灭**（非物理消灭，是失去以自己的名称/意义/声音存在于共同认知中的能力）

### 迁移规律（第11、12章）
可迁移程度：**话语权 > 解释权 > 定义权**。
推论：进入新场域后先获得声音 → 再获得解释地位 → 最后才能改变命名方式；三阶段间隔期最脆弱。
弱者策略是**换场**（把议题移到判准对自己有利的空间），且只对评价性议题有效、对事实争议无效。

### 符号（第11章，理论的新增维度）
符号 = 意义脱离说明单独流转的最小单位。压缩换速度，代价是丢掉条件与限定。
磨损（高频）/ 掏空（多主体争夺，指向不稳）/ 重置（强介入）。
符号是三权之间的接口：定义权赋初始含义、解释权持续填充、话语权推入流通。
**三层分属不同主体 → 围绕一个词的争论永远无法收束。**

### 五类场域（第11章）
政府（三权合一、信用共享、翻盘成本高）／公司（定义权生命周期最长、解释权最不稳定、危机只能动解释权）／
组织机构（制度化分配，争夺集中在换届期）／团队社群（最扁平，解释流动，沉默退出最难识别）／
互联网平台（定义隐蔽于算法、话语分散而算法集中、解释以小时计、用户迁徙=被离开而非被说服）

### 理论对话（第12章）
继承 5 项（维特根斯坦使用论／福柯话语实践／解释学＋霍尔编码／葛兰西"承认"／奥斯汀＋布迪厄"资格"）；
对话 8 位：福柯、布迪厄、维特根斯坦、葛兰西、奥斯汀、哈贝马斯、斯图亚特·霍尔、拉克劳&墨菲。
分歧 3 点：①承认功能可分 ②保留主体变量（福柯/拉克劳淡化持有者） ③改用条件安排而非意图作为判据（对应哈贝马斯）。
四项原创增量 = 功能三位拆分 / 组合命题 / 迁移规律 / 反噬机制，**全部承诺可证伪**。

### 适用边界（不得越界引用）
不处理生理认知机制；不解释权力全部运作；外推有场域限制；对意义内容不作对错判断。
自我批评很硬：缺少任一条边界，理论会滑向"关于一切的权力理论"或"关于技巧的清单"。

### 展示页设计决策（2026-10-04 确认）
- 用途：**对外发布 · 科普向**（读者是第一次接触，无社科背景）
- 载体：**单页滚动网页**
- 调性：**编辑阅读 · 浅色**（纸质感、衬线标题、可读性优先，适合长文滚动）
- 由此确定的技术选型：浅底 #FAF9F6 系 / 墨色正文 #2C2C2A / 主色深靛 #185FA5 系 /
  状态色只在失效·反噬处出现（#A32D2D 系）/ 标题用衬线、正文用无衬线 / 字号偏大、行距宽松
- 科普向的三条硬要求（必须遵守）：
  1. **术语首次出现必须转译**：每个抽象概念先给"大白话版本"，再给原文定义。
     如定义权→"这到底是个什么东西"；解释权→"这事怪谁，凭什么"；话语权→"谁说的话有人听"
  2. **案例永远排在概念前面**，不得先定义后举例
  3. **交互点必须自解释**，不能靠读者猜操作意图
- 结构调整：原 9 段扩为 11 屏，新增「问题引入」屏；八种状态不全讲——
  单权三态保留（有代入感），两权三组合保留但默认折叠，认知消灭单独作最坏结局一屏

### canvas 概念地图（2026-10-04 第九轮重做了展开态标签，旧规则已废）
- 逻辑尺寸常量 `LOGIC_W=960 / LOGIC_H=700`；`applyDpr()` 做高清适配（画布会被 CSS 缩到容器宽，约 778px）。
- **标签摆法**：展开时每个子标签**沿自己的射线外移固定 26px**贴住圆点，方向取 `subPos()` 返回的 `a`
  （动画中 `p→0` 时圆点收缩到节点中心，从坐标反推会得到零向量）。
  ~~奇偶错开 28/60~~、~~按"在中心点上方/下方"上下推 20px~~ **都已删除**——后者会把标签推到圆点
  的另一侧并打乱相邻标签的上下次序（实测 exp「第一解释」跑到圆点下方 12px）。
- **`plate()` 现签名** `plate(ctx,x,y,text,color,align,rayA)`；兜底**只沿射线外推 18/36px**，
  且须同时满足「不越界」与「与已放置标签不相撞」，否则保持原位。
- **接力标注**（归属/约束/破裂/门槛/管道/桥接/排序/归因/固化）**必须等子标签都写进 `placed` 之后再画**
  （旧代码画在所有标签之前，9 个里 6 个压住标签），沿连线法线按 `[0,±8…±56]` 试位。
- **维度几何（已定值，节点坐标一律不动）**：
  def(258,205,base2.79,arc2.1,dist170) / dis(702,205,base-0.20,arc1.9,dist165) /
  exp(480,510,base1.571,arc3.0,dist140)。节点一动就要同步改接力弧的 `ctrl` 与 `lx/ly`。
- **判断布局是否合法的硬指标**：相邻子节点弦距 `2·dist·sin(arc/(2(n-1)))` **必须 ≥ 标签宽**
  （4 字标签实测 74px；浏览器 `measureText` 与"每字 13px"估算逐字吻合）。
- **exp 的硬约束**：y=510 时只有 190px 竖向空间，**任何朝向都做不到 dist≥155**，
  只能「半径小 + 弧宽大」（172°/140）。要更舒展的深扇面必须把该节点上移
  （y→470 时可用半径升到 185，但要同步改两条接力弧）。
- **验证 canvas 的抓手**：`placed`（全局数组）每帧绘制后保存所有标签浮片的 `{x,y,w,h}`，
  顺序 = 6 个子标签 + 3 个接力标注。**断言直接读它**，不要重算 —— 那才是真实绘制数据。

## 工具与流程纪律（本项目反复踩过）
- **写文件内容一律用 Write/Edit 工具**，不要用 `python -c "…"` 拼长字符串 ——
  正文里的反引号会被 shell 当**命令替换**执行，脚本被拆碎（第八轮实踩，产出近 90 MB 报错）。
- **嵌套 heredoc 会被截断**：`python - <<'PYEOF'` 套在 `bash <<'EOF'` 里时内层只收到半行 →
  分析脚本先落成 `.py` 文件再跑。
- **shell 单引号陷阱（第九轮实踩）**：`CHK='(function(){…i+'x'+j…})()'` 里的单引号会**提前结束**
  shell 字符串，变量变成 `i+x+j`，浏览器报 `SyntaxError: Unexpected token ':'`。
  → 长脚本一律落成文件，用 `CHK="$(cat file.js)"` 读进来。
- **参数搜索脚本必须先拿已知坏样本自检**：第九轮我第一版把重叠判定写反
  （`gx>0 and gy>0` 实际是"已分离"），结果"找到"6154 个解却全是碰撞的、并对 exp 报 0 解 ——
  两个结论都是错的。**先确认判据在坏样本上会报错，才允许相信搜索结果。**
- **agent-browser 的守护进程**：同一脚本里 `close` 之后再 `open` 常失败
  （os error 10060/10061）。**一个脚本只开一个页面**；需要多页就分多次调用，中间 sleep 几秒。
- **验证 canvas 用 `atlas.toDataURL()` 做哈希对照**（比整屏截图可靠，不受滚动/翻页动画影响）。
